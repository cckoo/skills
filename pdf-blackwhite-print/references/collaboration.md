# 用户选择后的多 agent 协作

这里只说明**已明确获选**多 agent 后怎样执行；引用这个文件不表示已获授权。用户选择单 agent 时不要调用子 agent。

## 分工

- 主 agent：预审/试排、源文件和中间格式、分区与进度、统一排版、冲突裁决、哈希冻结及交付。
- 识别 agent：分配明确文件/页段/区域，恢复文字、图表层级，逐条核原图，输出独立修订与待决清单。
- 独立校对 agent：核对识别者的修改和未决项，优先核全部脚注/锚点、数字、专名、古字、公式、答案；有余力交叉查看语义和已知错形。不要只复读识别者结论。

不要在 skill 中规定固定数量。按实际槽位、页数和复杂度分配；可两段识别加一位校对，也可更小。单 agent 路线仍分开“识别、源图校核、输出核验”阶段，不能自称已由独立 agent 校对。

## 数据和工作边界

每个参与者使用相同源文件哈希和页序定义。给最小必要原始材料、范围、输入/输出文件约定；校对者拿到原图和修订，不应只拿清洗后的文字。

- 原始 OCR/提取数据只读；各 agent 写自己的修订文件，不能共同覆写一个 JSON 或最终 PDF。
- 以稳定记录 ID 合并，冲突不采用“最后写入者获胜”。不同新字需回源裁决，保留理由与核验者。
- 记录分工覆盖、已审范围、失败/未决页、锚点和排除区。阶段完成不等于整段已覆盖，迟到的 OCR 页也必须补审。
- 工作队列用页/区域认领和原子提交避免重复；不要让几个 agent 各自发起相同全书识别。可以从前后两段推进，使识别、校对都及时拿到材料，但重叠处需认领/去重。
- 限制本地 OCR 并发，子 agent 数与 OCR 工作进程数分别预算；不要每位 agent 都盲开占满 CPU 的进程。
- 已知错字回查、编号连续性、目录/图节点反查补在识别之后；高置信同错和人工抄录错误都可能存在。

## 冻结校样

主 agent 生成一个候选，写出内容快照哈希、PDF SHA256、页数和源页映射，明确告知所有审阅者“现在冻结”。**不能仅见文件时间改变就开始查稿**。

截图/意见包括 PDF 哈希、新版页号和原页位置。检查脚本发现 PDF 哈希在渲染中改变就失败；不要把新 PDF、旧映射与旧截图混在一起。

主 agent 收到具体缺陷后修数据/排版，再生成另一个版本并告知哈希；没有新版本信号时不自行读写工作稿。发布前确认所有通过意见属于相同最终哈希，复制后验证相同字节。数据不变、只修分页时复查受影响页及相邻页，不无故重做全部内容审核。

交付时只说明实际分工和核对范围，不把“多个 agent”本身当作零错误保证。
